
# ONLY IN Felinode FOLDER
## 2. Architecture & Directory Structure

The project follows a **Domain-Driven Feature Architecture** within the `src` folder to keep domains isolated and maintainable.

- `src/features/` - Modules grouped by domain (e.g., `learning`, `gamification`, `auth`, `home`, `nodes`, `settings`). **Keep domain-specific logic inside its respective feature folder.**
- `src/db_local/` - Local SQLite database interactions (`api_local.ts` and `db.ts`).
- `src/api/` - Cloud/Supabase communication and synchronization logic (e.g., `syncInfinityStats.ts`).
- `src/store/` - Global state management with Zustand.
- `src/components/` - Generic, reusable UI components not tied to a specific feature.
- `src/theme/` - Global styling, colors, and typography.
- `src/navigation/` - React Navigation navigators and route configurations.

---

## Core Coding Rules

### TypeScript & Quality
- **Strict Typing**: Always use TypeScript interfaces and types. Avoid `any`.
- **Modularity**: Extract complex logic into custom hooks (`useFeature.ts`) and pure services (`Feature.service.ts`). Keep components responsible ONLY for the UI.

### UI & Styling
- **RN Paper**: Prefer `react-native-paper` components for standard UI elements (Buttons, Text, Cards) to maintain theming consistency.
- **Animations**: Use `react-native-reanimated` for smooth UI transitions and micro-interactions. Try to keep the UI engaging but performant.

### State Management
- **Local State**: Use standard React `useState`/`useReducer` for state isolated to a single component.
- **Global State**: Use Zustand (`src/store/`) for cross-feature state (user session, global settings).

## 4. Domain-Specific Guidelines

### Database & Synchronization (Offline-First)
- All main app flows must work seamlessly offline by reading/writing to `src/db_local/api_local.ts`.
- Background/Idle Sync: Supabase sync should happen gracefully in the background. Handle merge conflicts with clear strategies (e.g., prioritize the *maximum* score to never downgrade user progress).

### AI Setup & Gemini Exercises
- AI Prompting must strictly define a **JSON output schema** for parsing reliability. (Do not rely solely on markdown strings if structured parsing is needed).
- All pedagogical explanations and "Theory" generated by AI must be in **Spanish**.
- Supported exercise types: `multiple_choice`, `scrambled_sentence`, `fill_blank`, `translate`, `pronunciation`, `select_pairs`.
- Keep AI service calls inside `src/features/learning/services/Gemini.service.ts` or similar isolated service files.

### Gamification (Infinity Mode)
- **Mechanics**: Track and sync lives and timers correctly. Maintain difficulty curves gracefully. Ensure offline progress syncs properly to Supabase when reconnected.

### Audio & TTS Management
- **Audio Focus**: TTS engines (Kokoro / Google) and background music (BGM) fight for audio focus. Handle `AudioFocusNotAcquiredException` gracefully.
- **Background Music (BGM)**: Always pause/stop BGM correctly within the cleanup function of `useFocusEffect` when leaving screens that play it.
- **Memory Leaks**: Ensure all audio assets (`expo-av`) are properly unloaded when components unmount.

## 5. Workflows

### 5.1. Creating a New Feature
1. Create a new directory in `src/features/[featureName]`.
2. Add necessary subdirectories inside it: `screens/`, `components/`, `services/`, `hooks/`.
3. Export the main entry points (e.g., the root screening of the feature) for `src/navigation/` to consume.

### 5.2. Implementing a Local-First Database Table
1. Define the table schema in `src/db_local/repositories` or designated initialization file.
2. Build CRUD operations in `src/db_local/repositories`.
3. Create the corresponding Supabase sync logic in `src/api/[syncFeature].ts`.
4. Ensure a merge conflict strategy is implemented (e.g., higher timestamp or score wins).
